rpx manages installable R packages. An existing project needs a valid `DESCRIPTION` with `Package` and `Version` fields and must contain the files required by `R CMD INSTALL`.

## Create the lockfile

Run `rpx lock` from the project or one of its subdirectories:

```bash
rpx lock
```

The command resolves dependencies from `DESCRIPTION` and writes `rpx.lock`. It records the current R version, repository configuration, requirements, selected packages, package sources, and system requirements. It does not install packages.

## Synchronize the library

Install the locked package set and the project itself:

```bash
rpx sync
```

Synchronization is strict. It installs missing packages, replaces version mismatches, and removes unexpected packages from the project library. Local projects and Git packages are reinstalled because their contents can change without a version change.

If `DESCRIPTION` or the repository configuration has changed since the lockfile was written, update the lockfile first:

```bash
rpx lock
rpx sync
```

## Check project state

Use `status` before committing or in CI:

```bash
rpx status
```

It checks that `DESCRIPTION`, repository configuration, the current R version, `rpx.lock`, the project package, and the installed library agree. A project in the expected state prints `Project is in sync`; drift produces a nonzero exit code and a diagnostic.

## System dependencies

On supported Linux distributions, rpx can install missing system packages before synchronizing R packages:

```bash
rpx sync --install-system
```

Install or check only the system packages without changing the R library:

```bash
rpx sync --install-only-system
```

The flags are mutually exclusive. Explicit non-interactive installation requires root access or passwordless `sudo`. macOS and Windows do not support these options.

## CI workflow

A typical CI job restores the exact project state and runs a script in that environment:

```bash
rpx sync
rpx status
rpx run Rscript scripts/check.R
```

Use `rpx sync --install-system` instead when a supported Linux runner should install system requirements automatically.

## What to commit

Commit both `DESCRIPTION` and `rpx.lock`. Do not commit the isolated library or shared package cache; `rpx sync` recreates the library from the lockfile.

If local state needs to be discarded, run:

```bash
rpx clean
rpx sync
```

`rpx clean` removes the current project library and shared rpx caches, so cached artifacts used by other projects will also need to be downloaded or rebuilt again.

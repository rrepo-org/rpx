# Publish packages

Set the destination in your package's `DESCRIPTION` using the namespace-qualified rrepo repository name:

```text
Repository: acme/internal
```

`Repository` identifies where this source package will be published. R repositories such as CRAN also use this field in published package metadata. Do not put a URL or an API key in `DESCRIPTION`.

Build and publish in separate steps:

```bash
rpx lock
rpx sync
rpx dist build
RREPO_API_KEY=... rpx dist publish
```

`rpx dist build` requires the locked dependencies to be synced and writes `dist/<Package>_<Version>.tar.gz`. `rpx dist publish` uploads that existing archive; it does not build or sync. Supply a `packages:write` API key through `RREPO_API_KEY`. In GitHub Actions, store the key as a secret and pass it to the publish step as an environment variable. Publishing does not prompt for credentials or use the local keyring.

To publish the same package to another repository without editing `DESCRIPTION`, use `--repository acme/staging` or set `RREPO_REPOSITORY=acme/staging`. The order of precedence is CLI option, environment variable, then `DESCRIPTION`. The destination always uses the canonical `https://rrepo.dev/<namespace>/<repository>/upload` endpoint.

Use `--artifact PATH` to upload an archive from a different location. rpx checks that its DESCRIPTION matches the current package name and version before uploading it.
